# Exemplar App & Benchmark Audit

> 审计 7 个已有 App 及其 benchmark suite 的写法，为 10 个目标 App 提供参考模板。所有计数来自源码实读。`未找到` 表示字段缺失。

评估框架共用（4 个 suite 一致）：
- `bench_env/task/base.py` 定义 `BaseTask`；`common_tasks.py` 定义 `AnswerTask`（自由文本/grounded 答案）、`CriteriaTask`（state/route 断言）、`build_grounded_checks`（AnswerSheet 判定）。
- `judge.py` 定义 `JudgeInput`（init vs last observation，`apps`/`os`/`apps_init`/`os_init`/`route`/`answer`）、`JudgeResult`、`StateComparator`（ID 字段感知的列表 diff；`[+=v]`/`[-=v]`；相对序检测）。
- `BaseTask.evaluate()` → `check_goals()` → `_evaluate_with_checks()` 计算 goal checks + 对照 `get_expected_changes()` 的意外状态变化检测。`always_ignore` 全局忽略 `os.time`/`os.runningApps`/`os.tasks`/`apps.answer_sheet`/`apps.*._temp`/`os.services.media_session` 等。
- grounded 模式：声明 `answer_fields` 的 task 经系统 App `answer_sheet` 走结构化字段（choice/number/text/repeatable），`build_grounded_checks` 逐字段按 matcher（`exact`/`exact_tc`/`number`/`date`/`time`/`duration`/`set`/`sequence`）匹配。非 grounded `AnswerTask` 用 `match_value`（regex/数字/子串 + 中文数字归一）。
- **7 个 suite 均未用 VLM judge**，判定全靠 state-diff + 文本匹配 + AnswerSheet 字段匹配。

- **对 10 目标 App 的参考价值**：canonical IM + 社交 feed + auth + pay super-app 模板，最富 exemplar。**Telegram** 直接（chat list/chat detail/message send 判定/contact 权限/blacklist/message→feed 转移 → `ConditionalReplyToBoss`/`PostMomentFromChat` 1:1 映射 Telegram 回复/转发；`new_sent_texts_to` id-diff 判定是 canonical "agent 是否发了正确文本" 范式）。**Gmail**（chat-thread + 条件回复 + label/blacklist → `BlacklistContact`/`SetFriendChatOnly` → 线程 mute/label/filter；`ReadMyWxid`/`ReadContactRegion` 是"读 profile 字段并报告"模板）。**Wallet**（`intentFilters: ACTION_PAY` + `pay/WalletPage`/`PaymentConfirmationPage` + amount/merchantName → 外部支付模板）。**Zhihu**（moments feed → 答案发布）。**Cainiao**/**Didi**/**ChinaMobile**（深 settings 树(26 页) + gated searchable features `SEARCHABLE_FEATURES` + auth-with-SMS/device-trust → 账户绑定服务 App）。**Amazon**/**Duolingo**/**GoogleDrive**（share-intent `ACTION_SEND` text/image → `/share/forward` + 内容转移判定 `ScenicPhotoToMomentsWithPhrase` → 跨 App handoff：分享商品链接/课程结果/文件链接）。
